# 可复用工具矩阵与 Programmatic SEO（G1/G2 必读）

## 核心原则

从**能力复用**而非“页面复制”出发。相同核心算法/模型可服务不同用户任务；SEO 独立页面必须拥有独立意图和真实功能/数据价值。PopNow 一类工具矩阵可以学习其架构，不能把页面数量等同于搜索成功。

## 五层架构

1. 能力层：计算公式、文件处理、图像生成、检索、格式转换等**可测试纯逻辑**。
2. 工具层：特定任务的输入 schema、输出 schema、边界及默认实例。
3. 内容层：工具页、独立场景、可引用原创数据、比较、指南、方法论。
4. 分发层：内部相关任务、搜索、真实行业资源、可选嵌入/分享/API。
5. 反馈层：工具完成率、非品牌搜索意图、下一工具使用、商业转化。

## URL 候选审核（逐条）

- 目标用户是否正在执行不同的任务？与已有 URL 是否同义词/同一步骤？
- 与现有页相比，有什么**具体且可见**的输入、输出、公式、数据或操作流程差异？
- 可以给出真实示例、来源、边界说明、独立 FAQ 吗？
- 用户从 SERP 进入后，能否立刻完成该意图而非再跳到同一个通用工具？
- 页面是否有到相关工具的逻辑链接？主内容是否可被 HTML 获取而不只出现在 JS 点击后？
- 有真实数据或用户需求证据吗？仅“关键词包含城市/型号/尺寸不同”不够。

**准入决策**：`ship`（独立有价值）、`merge`（同意图，增强已有页）、`experiment`（小规模验证）、`noindex`（用户有用但缺独立搜索价值）、`drop`（无真实价值）。无论创建速度多快都先审核。

## 示例：Concrete Calculator（只为解释方法，不自动套用）

- `concrete-slab-calculator`：长宽厚，输出体积、袋数、容错。
- `fence-post-concrete-calculator`：数量、孔径、孔深、立柱直径，输出净填充体积。
- `sonotube-calculator`：圆柱体积、管径、高度和根数。
- `4x4-slab-calculator`：仅与 slab 页尺寸不同 → 通常 `merge`，做可交互表或示例，不单独索引。
- `80lb-vs-60lb-concrete-bags`：材料包装选择、实测换算表 → 可能 `ship`，前提是有可靠独立信息。

## 内容批量生产规范

1. 从数据源生成 URL 清单，先审每页唯一价值和证据字段。
2. 工具模板共用组件、状态机、可访问性、Meta 与 schema 规则。
3. 页面特有：输入流程、例子/结果、公式来源、限制、测得的差异、相关任务推荐。
4. 发布前自动检查：slug 唯一、canonical 唯一、同意图冲突、证据缺失、空模块、内部死链、错误 schema。
5. 定期整合薄弱内容、合并未形成独立需求的尺寸或同义词页；不承诺固定 page count 或索引率。
