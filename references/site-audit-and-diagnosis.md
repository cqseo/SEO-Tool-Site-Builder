# 网站 SEO 审计与问题诊断（G0）

## 适用场景与默认边界

触发语义包括：“分析这个网站有什么问题”“检查 SEO”“看看这个站需要优化什么”“给我网站诊断报告”，以及用户直接提供一个 URL 并要求评估。默认只读；不得因为用户给了网址就推定已获准登录后台、修改代码、提交 Sitemap、改 DNS 或发布。

开始前先记录目标 URL、规范域名、日期/时区、网站类型、用户目标（自然搜索、线索/预约、工具使用或转化）和可用数据源。若范围不明确，先对首页和主要页面模板做初步审计，并明确范围，不要让一个缺失信息阻断可完成的公开检查。

## 检查流程

### 1. 建立 URL 与模板清单

- 打开首页，记录最终 URL、HTTP 状态（若可测）、跳转链、标题、主要 H1、可见主体内容和主要 CTA。
- 检查 `/robots.txt`、常见 Sitemap 入口及 robots.txt 中的 Sitemap 声明；验证 sitemap 中 URL 是否属于规范域名、是否可访问、是否包含重定向/404/非规范 URL。
- 从导航、页脚、面包屑、站点地图和页面内链识别核心页面。优先覆盖首页、服务/产品、分类/工具、重要内容、关于/联系/预约等模板。
- 大型站点采用分层抽样（按模板、流量/重要性、目录和状态码），报告抽样 URL 数和未覆盖范围；不要宣称已全站爬取。
- 尊重站点访问限制、robots.txt、速率限制和授权边界；不尝试绕过登录、WAF 或访问控制。

### 2. 技术 SEO 与抓取

逐项检查并记录实际证据：

- **状态码与跳转**：重要页面是否 200；是否存在循环/多跳重定向、软 404、错误 404、规范域名不一致；HTTP 是否跳转到 HTTPS；www/non-www、尾斜杠和大小写是否产生重复 URL。
- **索引控制**：robots.txt 是否意外阻止重要路径；HTML meta robots 与 HTTP `X-Robots-Tag` 是否有 noindex/nofollow；不要把 robots.txt 屏蔽误当成可靠的移除索引手段。
- **Canonical**：每个可索引页面是否有唯一、绝对、指向正确规范 URL 的 canonical；是否错误指向首页、旧域名、HTTP 版本或不相关页面；是否包含跟踪参数。
- **Sitemap**：是否可访问、语法是否有效、URL 是否规范且返回 200、是否包含 noindex/重定向/404；Sitemap 提交状态与实际收录状态必须分开描述。
- **页面可见性**：主内容是否出现在 HTML/渲染后的页面中；是否过度依赖 JS 导致正文或链接不可见；是否有关键资源加载失败、控制台/网络错误（仅在有浏览器工具时）。
- **内部链接**：失效内链、孤立页面（仅在有足够 URL 数据时）、锚文本过于泛化、重要页面点击深度、导航/面包屑一致性。
- **国际化与结构化数据**：仅在实际使用时检查 hreflang 对等关系、语言/地区 URL；检查 Schema 类型、必填字段、语法和可见内容是否一致。不要默认添加 FAQPage，也不要输出虚假评分、评论或商家信息。
- **安全与可访问性边界**：不要输出密钥、个人信息或敏感后台数据；发现公开泄露风险只记录最少必要证据并建议安全处理。

### 3. 页面 SEO 与内容质量

- Title：是否缺失、重复、过长/过短、描述不清或与页面任务不符。字符数仅作诊断线索，不作为固定排名规则。
- Meta description：是否缺失/重复、是否准确总结页面并帮助用户判断点击价值；不要声称它是直接排名因素。
- H1/H2：主标题是否清晰，层级是否合理，是否存在多个无意义 H1 或标题仅为装饰文本。
- 搜索意图与独立价值：页面是否真正完成用户任务，是否只替换关键词/城市名形成近重复页，是否有真实示例、数据来源、流程、结果、限制或差异化信息。
- 内容可信度：检查来源、日期、作者/机构信息、联系方式、免责声明是否适合站点类型。不得编造资历、专家背书、用户评价或原创研究。
- 图片与媒体：ALT 是否描述信息性图片，装饰图是否避免冗余 ALT；文件大小、格式、尺寸、懒加载与首屏关键图优先级是否合理。
- 内链与信息架构：相关页面是否互相链接，重要页是否可从导航/分类到达，锚文本是否准确且自然；避免机械堆砌关键词。
- 本地商家（适用时）：名称、地址、电话、营业时间、服务区域和地图是否一致；预约 CTA 是否有效；不要推断或编造商家信息。
- 工具/计算器（适用时）：实际输入、输出、单位、公式来源、边界错误、重置/复制/下载流程；不能只因为页面有控件就判定功能可用。

### 4. 性能、移动端与转化体验

- 至少在 320px、390px、768px 和桌面宽度检查布局（如果真实浏览器/截图工具可用）；关注横向溢出、被遮挡的 CTA、菜单、表格、弹窗、表单和图片裁切。
- 若 PageSpeed Insights / Lighthouse / CrUX 等工具可用，记录 URL、日期、设备模式、分数/指标来源和样本类型；区分实验室数据与真实用户数据。不可用时将其标为 `NOT RUN`，不估算分数。
- 检查 LCP、INP、CLS 相关问题的可见线索：首屏图片、渲染阻塞资源、过大脚本、布局偏移、字体和第三方组件。没有现场数据时只能写“可能原因/建议测量”，不能宣称 Core Web Vitals 已失败。
- 关注主 CTA 是否清晰、表单是否可完成、电话/预约链接是否正确、错误状态是否可理解。不要为了 SEO 改坏转化流程。
- 可访问性检查键盘操作、焦点、表单标签、触摸目标、对比度与结果提示；只对实际测试过的项目标 PASS。

### 5. 搜索可见性与数据

- 若有授权 GSC/GA4 连接器，先复用已有属性，记录属性、时间范围、时区、地区、设备、查询/页面和数据延迟；不要重复验证已完成的属性。
- GSC 可用于分析曝光、点击、CTR、平均排名、URL Inspection 和 Live Test；GA4 可用于查看关键 CTA、工具启动/成功和转化路径（前提是相关事件已正确设置）。
- 无 GSC 权限时，不得声称某页“已收录/未收录”、报告实际排名或索引数量。`site:domain.com` 结果只能作为不完整的辅助观察。
- 竞品分析仅在用户要求或确实有助于诊断时开展；把页面可见事实、第三方估算和推断分开，不照搬竞品代码、文案或品牌资产。

## 问题分级

- **P0 — 立即处理**：网站/核心页面不可用；重要 URL 被意外全站 noindex 或被错误 robots 规则阻断；canonical 大范围指向错误域名；敏感数据/密钥公开；生产故障或关键转化完全失效。
- **P1 — 高优先级**：关键页面状态码/跳转异常、Sitemap 大量错误、核心模板缺失标题/H1、主内容无法抓取、严重移动端问题、明显的速度瓶颈、重要内链断裂、预约/表单主路径故障。
- **P2 — 常规优化**：内容深度与意图匹配、描述与标题优化、图片 ALT/压缩、内链补充、Schema 细节、可访问性和次要 UI 改进。

同时标注执行类型：`配置`、`内容`、`代码`、`数据/权限`；工作量估算为 `S/M/L`，必须说明这是粗略估计而非承诺。

## 证据与状态规范

每条发现至少包含：

1. URL 或受影响模板；
2. 实际观察到的内容/状态/工具返回值；
3. 问题解释与用户/搜索影响；
4. 推荐修复动作；
5. 优先级、执行类型、粗略工作量、置信度；
6. 状态：`PASS`、`FAIL`、`NOT RUN` 或 `BLOCKED`；
7. 验证方法及尚未验证的部分。

证据类型标记：`OBSERVED`（本次实际观察）、`CONNECTED DATA`（来自授权数据源）、`INFERRED`（根据证据推断）、`NOT VERIFIED`（尚未验证）。不要将推断写成事实。

## 输出结构

1. **执行摘要**：整体判断、最重要的 3–5 个问题、审计覆盖范围和限制。
2. **按优先级的问题清单**：P0/P1/P2；具体 URL、证据、影响、修复、工作量、状态。
3. **分阶段行动计划**：先修阻断问题，再修模板级问题，最后做内容/体验增强；避免把所有建议都标成高优先级。
4. **需要权限/数据的检查**：GSC、GA4、真实浏览器、PageSpeed、日志、CMS 后台等。
5. **未验证项与下一步**：明确哪些只是建议、哪些需要实测。

只读审计结束时不自动改动网站。如果用户明确要求直接修复，先基于报告确认最小变更范围，读取当前文件/部署状态、保护现有改动，再执行 G2/G3 对应流程并做回归测试。
