# 工具站平台架构与跨类型产品实现（G2）

## 最小系统设计

- **配置层**：`id/slug`, 语言, job, inputSchema, outputSchema, defaultSample, algorithmId, testedExamples, relatedToolIds, sourceLinks, seo metadata, indexDecision。
- **能力层**：计算/转换/调用 AI 的独立模块，有确定输入输出和纯逻辑单测。第三方 API 使用服务端代理，密钥不进入前端。
- **交互层**：表单字段、状态变化、错误反馈、结果、复制/下载/打印/分享、下一工具推荐；支持键盘与屏幕阅读器。
- **内容层**：静态或 SSR 可抓取主要解释/示例；交互 JS 不应成为核心 SEO 文本的唯一来源。
- **服务层（按需）**：登录、计费、队列、速率限制、文件清理、事件日志。只在需求需要时引入，避免 MVP 过度设计。

## 多工具复用与参数传递

- 为能力模块设置版本、单测和契约；UI 不直接复制业务公式。
- 工具间传参采用显式映射（source output → target input），只传播非敏感必要字段。价格/客户信息不要默认放入 URL。
- 页面配置必须经过类型/格式校验；相关工具不是随机列表，而是用户任务下一步。
- 更新公共核心时必须回归所有受影响工具，保持同类计算的一致精度与取整策略。

## 不同工具类型的额外 QA

| 类型 | 必须增加的测试 |
|---|---|
| 计算器 | 精度、单位、边界、负值、损耗、净量/毛量、取整 |
| 格式转换器 | 文件损坏、超限、MIME/扩展名不一致、隐私、无网络、下载文件有效 |
| PDF/图片 | 大文件、方向、透明度、元数据隐私、批量处理、可读性 |
| AI 工具 | 超时、额度预留/退款、任务幂等、模型失败、提示词注入防护、版权/使用约束 |
| B2B 工作流 | 价目版本、数据导出、权限、跨设备恢复、审批与审计 |

## 技术栈选择

Astro 静态内容+交互岛适合内容重、工具计算在浏览器完成的站；Next.js 更适合深度用户态/SSR 应用；Cloudflare Pages/Workers 或 Vercel 按需求选。评估维度：部署与回滚、静态 SEO 输出、缓存、可测试性、团队维护、第三方依赖和成本。不得为了跟随竞品强行更换已有可用架构。

## 安全与质量

- 上传大小、文件格式、调用频率、请求验签/鉴权、XSS、滥用和日志中的敏感信息检查。
- 单元/集成/E2E 各自记录；没有真实浏览器数据时明确未做 E2E。
- 单页面演示样例、生产真实定价或计算数据不混淆；演示数据明显标注。
